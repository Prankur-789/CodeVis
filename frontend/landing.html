How It Works

From keystrokes to control-flow diagram

Every step below runs against real parsers and a real sandboxed compiler/interpreter — nothing on this page is mocked.

1

Write code

Use the Monaco-powered editor (the same engine behind VS Code) with syntax highlighting, bracket matching, and code folding for Python, C, or C++.

2

Run it safely

Your code executes inside a resource-limited sandbox: CPU time, memory, process count, and wall-clock limits are all enforced, with automatic cleanup after every run.

3

Parse the real structure

A language-specific adapter builds a genuine AST (Python's own `ast` module, pycparser for C, or a hand-written recursive-descent parser for C++) — never regex or keyword guessing.

4

See the flow

The AST is translated into a language-independent flowchart graph and rendered as an interactive, pannable, zoomable diagram with click-to-highlight source mapping.

Supported Languages

Three languages today, more by design

Every language plugs into the same common intermediate representation, so adding a fourth is an adapter, not a rewrite.

Python
Full statement-level AST via the standard library `ast` module.
C
Real parsing via pycparser, with line-number-preserving preprocessing.
C++
A hand-written tokenizer + recursive-descent parser for a documented control-flow subset.

Safe Code Execution

Defense in depth, honestly documented

Every run gets a fresh temp directory, a stripped environment, and hard limits on CPU time, memory, process count, and wall-clock duration — enforced via os.setsid() plus a process-group-wide kill so that even a program which forks children cannot outlive its timeout. This is real process-level isolation, not a kernel/VM-level sandbox; see docs/TECHNICAL_DOCS.md for the full threat model and the container-based upgrade path for multi-tenant production deployments.
